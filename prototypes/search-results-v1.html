Results for Integration Broker REST service returns HTTP 500
Source-backed troubleshooting snapshot 3 Oracle sources

An HTTP 500 returned by an external system can surface in Integration Broker as an HTTP target connector gateway exception. Start by locating the exact transaction and collecting gateway-level evidence before changing configuration.

  1. Check the transaction in Service Operations Monitor.
  2. Inspect the integration gateway message/error logs for the outbound request and returned response.
  3. If needed, enable gateway logging for the monitored transaction and reproduce the failure.
  4. Determine whether the 500 originated from PeopleSoft processing, the gateway, or the external endpoint.
Sources: Oracle PeopleTools 8.63 Integration Broker documentation [1] [2] [3]
AI diagnostic suggestion: After capturing the actual outbound request, compare its URL, method, headers, authentication and payload with the known-good request from Postman. This is an interpretation/recommendation, not a direct Oracle documentation claim.
